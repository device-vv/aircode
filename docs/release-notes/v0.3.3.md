# AIRcode v0.3.3

## English

Version 0.3.3 focuses on agent reliability, cancellation, response integrity, and visible progress.

- All 17 supported syntax grammars use language highlight queries with deterministic overlap resolution; Markdown inline syntax is included. Precise token ranges and Unicode edits are covered by regression fixtures.
- File writes validate existing and new ancestry, block link escapes and protected paths, use same-directory atomic replacement, and check cancellation before replacement. Nested project directories can be created as part of a write. File discovery now reports truncation reliably and search can target individual files.
- Empty or reasoning-only responses do not count as completed tasks. Each queued agent retains its own visible project history and receives bounded, labelled shared results. Leader task order is preserved.

- Project-scoped named agent profiles support explicit `@alias task` assignments and leader-planned shared tasks. A bounded sequential queue gives only one agent tools at a time, preserves the existing approval flow, labels speakers and results, and stops cleanly on errors, denial, cancellation, project changes, or stale events. Profiles contain provider snapshots but no API keys.
- Native Markdown chat export saves the complete visible conversation with project and speaker labels, original code blocks, and partial/error/cancelled states. Hidden reasoning and raw tool arguments are excluded, and the portable snapshot remains separate from resumable internal history.
- Long agent turns retain the original user goal and system instructions. Small conversations are sent unchanged; overflowing history keeps recent messages from both before and after the latest goal. Complete tool exchanges stay atomic, an oversized latest exchange is reported instead of silently dropped, and truncation is stated explicitly.
- Commands have a 120-second default timeout, accept a bounded 1–600 second override, continuously drain output into a fixed-size buffer, and stop the process tree on cancellation or timeout. Windows command processes are hidden and extended/UNC current directories are normalized before launch.
- Agent commands and output stay in a labelled activity view with bounded previews. They are not injected into the user's interactive shell.
- While a `write_file` call is still streaming, the client extracts a bounded, throttled proposal snapshot from the partial arguments and shows it in a clearly labelled panel when that file is already the active editor tab. This preview never writes files, changes dirty documents, moves the cursor, or grants approval. Approval still uses the complete call and bounded diff.
- The project tree and editor show the active AI file and highlighted ancestor folders while code is still generating, plus a compact localized AI badge and completed-write markers, without moving focus.
- Successful agent writes refresh clean open tabs, including inactive tabs. Dirty buffers are never replaced; the conflict and on-disk update are reported instead.
- Stop and project switch clear active progress, and stale stream/tool events are ignored.
- AI streams distinguish normal completion from token-limit, content-filter, provider-error, truncated, and stalled outcomes. Response headers have their own deadline, and SSE heartbeats cannot indefinitely extend the deadline for real content, reasoning, or tool progress. Unfinished output is not marked complete.
- Up to two bounded retries are attempted for transient connection errors and rate limits, but only before any text, reasoning, usage, or tool action has been exposed. Once output is visible, the client fails rather than risking duplicate actions.

### Packaging

Native unsigned portable archives are produced for Windows x86_64, Linux x86_64, and macOS arm64, with SHA-256 checksums. Windows is the primary manual-validation target for this release. Linux and macOS packages use the same platform dependencies as CI but their graphical runtime has not been manually verified.

The Linux package is built on Ubuntu 22.04 to avoid requiring the newest glibc from a moving runner image. Desktop font and window-system libraries are still required. The macOS arm64 binary declares a minimum OS version of 11.0.

### Known limits

- Shell commands still run with user permissions and are not sandboxed. Process-tree termination and bounded output are reliability measures, not a security boundary.
- Token-limit responses are reported as incomplete rather than automatically continued.
- Streamed write previews are throttled, bounded snapshots of incomplete arguments. They are not a guarantee of the final file contents; approval and refreshing still use the complete tool call and existing cleanup rules.
- LSP, debugging/DAP, Git operations, and signed installers remain out of scope.

## Русский

- Для всех 17 поддерживаемых грамматик используются правила подсветки языка с разрешением пересекающихся диапазонов, включая строчный синтаксис Markdown. Проверены точные диапазоны токенов и редактирование Unicode.
- Запись проверяет существующие и новые родительские папки, блокирует выход через ссылки и защищённые пути, заменяет файл атомарно и проверяет отмену перед заменой. Вложенные папки создаются при записи. Ограниченный список файлов явно отмечается, поиск работает и по отдельному файлу.
- Пустой ответ или одни рассуждения не считаются завершённой задачей. Каждый агент получает свою видимую историю текущего проекта и ограниченные общие результаты. Порядок задач из плана ведущего сохраняется.

Версия 0.3.3 посвящена надёжности агента, отмене, целостности ответов и видимому прогрессу.

- Именованные профили агентов на уровне проекта поддерживают явные задания `@alias task` и общие задачи с планом лидера. Ограниченная последовательная очередь выдаёт инструменты только одному агенту, сохраняет прежние подтверждения, подписывает ответы и результаты и корректно останавливается при ошибке, запрете, отмене, смене проекта или устаревшем событии. Профили содержат снимки конфигурации без API-ключей.
- Нативный экспорт чата в Markdown сохраняет всю видимую переписку с названием проекта, именами агентов, исходными блоками кода и неполными/ошибочными/отменёнными состояниями. Скрытые рассуждения и сырые аргументы инструментов исключены, а переносимый снимок отделён от возобновляемой внутренней истории.
- В длинных сессиях агента сохраняются исходная цель пользователя и системные инструкции. Небольшая история отправляется без изменений; при переполнении сохраняются свежие сообщения до и после последней цели. Завершённые обмены инструментов остаются целыми, а слишком большой последний обмен явно вызывает ошибку вместо тихого удаления; усечение указывается.
- У команд тайм-аут по умолчанию 120 секунд с ограничением 1–600 секунд. Вывод постоянно вычитывается в буфер фиксированного размера, а при отмене или тайм-ауте завершается дерево процессов. Для Windows команды запускаются скрыто, а расширенные и UNC-пути нормализуются.
- Команды и вывод агента остаются в помеченном журнале с ограниченным предпросмотром и не вставляются в интерактивную оболочку пользователя.
- Пока вызов `write_file` ещё передаётся, клиент извлекает ограниченный и throttled снимок частичных аргументов и показывает его в явно подписанной панели, если этот файл уже открыт в активной вкладке. Предпросмотр не записывает файлы, не меняет несохранённые документы, не двигает курсор и не даёт разрешение. Утверждение по-прежнему использует полный вызов и ограниченный diff.
- Дерево проекта и редактор показывают текущий файл ИИ и подсвеченные родительские папки уже во время генерации кода, а также компактный локализованный бейдж ИИ и отметки завершённой записи, не забирая фокус.
- После успешной записи агента чистые открытые вкладки, включая неактивные, перезагружаются. Несохранённые буферы не перезаписываются: показывается конфликт и состояние файла на диске.
- Остановка и смена проекта очищают активный прогресс; устаревшие события потоков и инструментов игнорируются.
- Потоки ИИ различают нормальное завершение, лимит токенов, content filter, ошибку провайдера, обрыв и зависание. Для заголовков ответа есть отдельный дедлайн, а SSE-heartbeat не может бесконечно продлевать срок ожидания реального контента, рассуждений или прогресса инструмента. Незавершённый вывод не помечается завершённым.
- Для временных сетевых ошибок и rate limit допускаются не более двух ограниченных повторов, но только до появления текста, рассуждений, usage или действия инструмента. После видимого вывода клиент завершается с ошибкой, чтобы не дублировать действия.

### Пакеты

Публикуются нативные неподписанные portable-архивы для Windows x86_64, Linux x86_64 и macOS arm64 с контрольными суммами SHA-256. Основная ручная проверка этого релиза выполняется для Windows; Linux- и macOS-пакеты используют те же зависимости, что и CI, но их графический запуск вручную не проверялся.

### Известные ограничения

Linux-пакет собирается на Ubuntu 22.04, чтобы не требовать новейшую glibc из меняющегося образа сборки. Системные библиотеки шрифтов и графического окружения всё ещё необходимы. У бинарника macOS arm64 указана минимальная версия ОС 11.0.

- Shell-команды по-прежнему работают с правами пользователя без песочницы. Завершение дерева процессов и ограничение вывода повышают надёжность, но не являются границей безопасности.
- Ответы с лимитом токенов помечаются как незавершённые и не продолжаются автоматически.
- Потоковый предпросмотр записи — это throttled и ограниченный снимок неполных аргументов. Он не гарантирует итоговое содержимое файла; утверждение и обновление редакторов по-прежнему используют полный вызов и прежние правила.
- LSP, отладка/DAP, Git и подписанные установщики по-прежнему не входят в релиз.
